HOW A ROW IS BUILT
--------------------
Each row starts from one ISM ticket, matched by:
  project = ISM AND resolved >= <fromDate> AND resolved <= <toDate>
  ORDER BY cf[16311] DESC
(no status/resolution filter — see NOTE ON SCOPE below)

Then the linked FIN ticket is found one of two ways:
  1. Reselling pattern : FIN linked DIRECTLY on the ISM ticket's issuelinks.
  2. Service pattern    : no direct FIN link — the ISM ticket's linked PRJ-/AUS-
                          tickets are checked instead, and THEIR issuelinks are
                          searched for a FIN- key.
  If neither path finds a FIN ticket (e.g. ISM-82237, ISM-84077), the row is
  still emitted with all FIN-sourced columns blank — this is expected, not a bug,
  when the ISM ticket genuinely has no linked FIN ticket in Jira.

NOTE ON SCOPE
---------------
The JQL has no status/resolution filter, so it also picks up tickets resolved
as e.g. "Duplicate" or "Won't Fix" — these typically have most fields blank/zero
because they were abandoned before financial data was entered (see ISM-84077).

IMPORTANT — SHARED FIELD IDS, ISM vs FIN SIDE CAN DIFFER
----------------------------------------------------------
Many of these custom field IDs are configured on BOTH the ISM and FIN projects
independently, and are NOT guaranteed to hold the same value on both sides.

  Confirmed to differ (business decision made: use ISM — see history log on
  ISM-82091, which shows these were once equal to FIN's frozen values and later
  updated only on the ISM side):
    License Amount ($), Profitability, Invoice Amount in local currency (Without Tax)

  Confirmed populated on BOTH sides with the SAME value in every sample checked
  (no conflict, either side would work — FIN kept for these since that's where
  the finance team enters them):
    Company Name, Billing Entity, Billing Frequency, OEM Purchase Amount ($),
    Segment BU, Market Team

CASCADING (PARENT + CHILD) SELECT FIELDS
------------------------------------------
Exchange Rate Type, Market type, OEM, and Region code are Jira "cascading
select" fields — the API returns {value, child:{value}}, and the correct
display value is "Parent - Child" (e.g. "India - INR per USD"). Reading only
the parent silently drops the child (fixed via api/server.js's pickCascading()).

Legend
------
  System field : built-in Jira field, not a custom field (id/key/summary/status.name)
  Derived      : not a raw field — computed from issuelinks (linked issue key)

NOTE ON DUPLICATE FIELD NAMES
------------------------------
Three of these column names have more than one custom field in Jira sharing the
exact same label. The field ID below is the one confirmed (via live data) to
actually hold the real value; the other duplicate is listed as a comment so it
isn't picked by mistake later.

  OEM         → customfield_11092 (confirmed)   [decoy: customfield_11054, unused]
  Segment BU  → customfield_11384 (confirmed)   [decoy: customfield_11303, unused]
  Market Team → customfield_11373 (confirmed)   [decoys: customfield_11304 "Market Team.",
                                                  customfield_14243 "Market Team_" — different labels, not real dupes]
